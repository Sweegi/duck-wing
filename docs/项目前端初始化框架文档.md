# 项目前端初始化框架文档

## 一、项目概述

本项目为多端前端工程，包含以下三个子项目：

| 端         | 技术栈                    | 说明           |
|------------|---------------------------|----------------|
| 网站前台   | Vue 3                     | 面向 C 端的 Web 站点 |
| 小程序 / H5 | uni-app                   | 微信小程序及 H5 页面 |
| 后端管理平台 | Element Plus + Vben Admin | 面向运营/管理的后台系统 |

全局样式统一采用 **TailwindCSS**。

---

## 二、Node 版本要求

| 项目           | 建议 Node 版本 | 说明 |
|----------------|----------------|------|
| 全项目         | **v24.x LTS** 或 **v22.x LTS** | 建议使用当前最新 LTS 版本 |

- 当前推荐：**Node.js v24.13.0 (LTS)** 或更高 LTS 版本。
- 可通过 [Node.js 官网](https://nodejs.org/) 下载，或使用 nvm 管理多版本：

```bash
# 使用 nvm 安装并切换
nvm install 24
nvm use 24
node -v   # 应显示 v24.x.x
```

## 三、技术栈明细

### 3.1 网站前台（Vue 3）

- **框架**：Vue 3（Composition API + `<script setup>`）
- **构建**：Vite
- **语言**：TypeScript

- **框架**：uni-app（Vue 3 语法）
- **构建**：Vite（uni-app 官方推荐）
- **语言**：TypeScript
- **样式**：TailwindCSS（需配置 uni-app 兼容）
- **端**：微信小程序、H5

### 3.3 后端管理平台（Vben Admin）

- **框架**：Vue 3 + Vben Admin（基于 Vue-Vben-Admin）
- **UI**：Element Plus
- **样式**：TailwindCSS（与 Vben 内置样式配合）
- **构建**：Vite
- **语言**：TypeScript

## 六、Mock 数据服务

为方便前端开发联调，采用 **自建小 Node 服务 + JSON/YAML 配置** 的轻量 Mock 方案：接口与返回数据均用文本配置，支持按场景返回成功或各种错误，三个前端项目共用同一 Mock 服务。

### 6.1 方案要点

- **共用**：web、uni-app、admin 在开发环境将 API base URL 指向同一 Mock 服务（默认端口 **5176**）。
- **文本配置**：接口路径、方法及多组返回（成功/各类报错）写在 `apps/mock` 下的 JSON 或 YAML 配置文件中。
- **场景切换**：通过请求参数 `?__scenario=xxx` 或请求头 `X-Mock-Scenario: xxx` 选择返回哪一组数据，便于联调成功态与各种错误态。

### 6.2 目录与入口

- **路径**：`apps/mock/`
- **入口**：`apps/mock/server.js`（或 `index.js`），读取配置文件并注册路由，无数据库、依赖仅 Express（或 Fastify）等轻量框架。
- **配置**：`apps/mock/config.json` 或 `config.yaml`（见下文格式）。

### 6.3 配置文件格式（JSON 示例）

```json
{
  "port": 5176,
  "routes": [
    {
      "path": "/api/login",
      "method": "post",
      "responses": {
        "success": { "status": 200, "body": { "code": 0, "data": { "token": "mock-token" } } },
        "wrongPassword": { "status": 200, "body": { "code": 40001, "message": "密码错误" } },
        "userLocked": { "status": 200, "body": { "code": 40002, "message": "账号已锁定" } },
        "serverError": { "status": 500, "body": { "message": "Internal Server Error" } }
      }
    },
    {
      "path": "/api/user",
      "method": "get",
      "responses": {
        "success": { "status": 200, "body": { "code": 0, "data": { "name": "张三" } } },
        "unauthorized": { "status": 401, "body": { "message": "未登录" } }
      }
    }
  ]
}
```

- **默认**：不传 `__scenario` 或 `X-Mock-Scenario` 时，返回该接口下 `success` 对应的 `status` 与 `body`。
- **指定场景**：请求时带 `?__scenario=wrongPassword` 或 Header `X-Mock-Scenario: wrongPassword`，则返回该 key 对应的响应（如 40001、500、401 等），用于模拟操作正确与各种报错。

### 6.4 前端对接

- 开发环境将三个子项目（web、uni-app、admin）的 API 基础地址配置为 Mock 服务地址，例如：`http://localhost:5176`（Docker 内可为 `http://localhost:5176` 或按容器网络配置）。
- 联调某错误场景时，在请求中加上 `__scenario=xxx` 或 `X-Mock-Scenario: xxx` 即可（可在 axios/request 拦截器中根据环境变量或本地开关统一加）。

### 6.5 与 Docker / Makefile 的衔接

- **Docker**：镜像仅提供 Node 环境，代码与 node_modules 通过挂载使用。先 `make docker-up` 启动容器，再 `make docker-install` 安装依赖，然后通过 `make docker-dev-mock`、`make docker-dev-web` 等在容器内启动 Mock 与三端（见第七、八节），保证三端共用同一 Mock 服务。
- **本地**：可通过 `make dev-mock` 单独启动 Mock，或通过 `make dev-all` 与三端一并启动（见第八节 Makefile）。

## 七、Docker 开发环境

### 7.1 轻量化思路

- **镜像**：仅提供 Node 24 运行环境，不 COPY 代码、不 RUN npm install，镜像体积小。
- **代码与产物**：通过目录挂载使用宿主机上的源码、配置文件、`node_modules`、`dist` 等，不写入镜像，不影响镜像大小。
- **install / 运行 / build**：均在容器内通过挂载的目录执行，由 **Makefile** 调用 `docker run` 或 `docker exec` 完成（见第八节）。

### 7.2 Dockerfile

以下 Dockerfile 只构建 Node 环境，不包含项目文件。

**路径**：项目根目录下 `docker/Dockerfile`

```dockerfile
# 仅提供 Node 24 环境，不复制代码、不安装依赖
FROM node:24-alpine

WORKDIR /app

# 保持容器常驻，便于 Makefile 通过 docker exec 执行 install / dev / build
CMD ["sleep", "infinity"]
```

### 7.3 使用方式

- 构建镜像：`make docker-build`
- 启动容器（挂载当前目录，映射端口）：`make docker-up`（后台常驻，用于后续 exec）
- 在容器内安装各项目依赖：`make docker-install`
- 启动服务：通过 Makefile 在容器内执行，例如 `make docker-dev-web`、`make docker-dev-mock` 等（见第八节）。
- 进入容器：`make docker-shell`
- 停止容器：`make docker-down`

本地不挂容器时可直接执行 `make install`、`make dev-all` 等（见下方 Makefile）。

## 八、Makefile

**路径**：项目根目录 `Makefile`

用于统一执行安装、开发、构建及 Docker 相关命令。脚本内容以仓库内 `Makefile` 为准，此处仅说明使用方式。

### 8.1 本地执行（不挂 Docker）

| 命令 | 说明 |
|------|------|
| `make install` | 检查 Node 版本后，在 apps/web、apps/uni-app、apps/admin、apps/mock 内分别执行 `npm install` |
| `make dev` | 根目录执行 `npm run dev`（若根有 dev 脚本） |
| `make dev-all` | 同时启动 Mock（5176）+ 三端：web 5173、uni-app H5 5174、admin 5175 |
| `make dev-mock` | 仅启动 Mock 服务（端口 5176） |
| `make dev-web` / `make dev-uni` / `make dev-admin` | 分别启动前台、uni-app H5、管理后台 |
| `make build` | 在 web、uni-app、admin 内依次执行 `npm run build` |
| `make clean` | 删除各项目下 node_modules 与 dist |

### 8.2 Docker 相关

需先执行 `make docker-build` 构建镜像（仅 Node 环境），再 `make docker-up` 启动容器（挂载当前目录、映射 5173/5174/5175/5176）。

| 命令 | 说明 |
|------|------|
| `make docker-up` | 启动容器并后台常驻，供后续 exec 使用 |
| `make docker-install` | 在容器内为 web、uni-app、admin、mock 分别安装依赖（需先 docker-up） |
| `make docker-dev-web` / `docker-dev-uni` / `docker-dev-admin` / `docker-dev-mock` | 在容器内启动对应服务（需先 docker-up、docker-install；每终端一个） |
| `make docker-dev-all` | 在容器内同时后台启动 Mock + 三个前端服务 |
| `make docker-build-all` | 在容器内对 web、uni-app、admin 执行 build |
| `make docker-shell` | 进入容器 shell |
| `make docker-down` | 停止并移除容器 |

## 九、初始化步骤摘要

1. **确认 Node 版本**：安装并切换至 Node v24.x LTS（或文档中约定的版本）。
2. **（可选）一键初始化**：在项目根目录执行 `./init.sh`，可自动创建 `apps` 目录结构、初始化 web（Vite Vue TS）、mock（server.js + config.json）、占位 uni-app/admin，并写入轻量版 `docker/Dockerfile`。若某子目录已存在则跳过。
3. **或手动创建**：按上述目录结构创建 `apps/web`、`apps/uni-app`、`apps/admin`、`apps/mock`，并初始化各子项目：
   - 前台：`npm create vite@latest apps/web -- --template vue-ts`，再接入 TailwindCSS。
   - uni-app：使用 HBuilderX 或 CLI 创建至 `apps/uni-app`，选择 Vue3 + TS。
   - 管理端：基于 [Vben Admin](https://github.com/vbenjs/vue-vben-admin) 克隆或模板初始化到 `apps/admin`。
   - Mock：在 `apps/mock` 下新建 `server.js` 与 `config.json`（或 `config.yaml`），按第六节格式配置接口与多场景返回，依赖仅需 Express 等轻量框架。
4. **配置 TailwindCSS**（若使用 `init.sh` 已生成 web，可在此项目内配置）：在三个子项目中分别安装并配置 `tailwindcss`，保证全局样式统一。
5. **开发环境 API 地址**：将 web、uni-app、admin 在开发环境的 API base URL 指向 Mock 服务（如 `http://localhost:5176`），便于三端共用 Mock。
6. **（可选）Docker**：将 `docker/Dockerfile`（仅 Node 环境，无代码拷贝）与根目录 `Makefile` 放入项目。执行 `make docker-build` 构建镜像，`make docker-up` 启动容器（挂载当前目录），`make docker-install` 在容器内安装各项目依赖，再通过 `make docker-dev-web`、`make docker-dev-mock` 等启动服务（见第七、八节）。
